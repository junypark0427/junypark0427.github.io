# 배포 방식 업그레이드

GitHub Pages에서는 `gh-pages` Branch를 이용하는 방식과 GitHub Actions를 통해 직접 배포하는 방식을 사용할 수 있다.

이번에는 기존의 Branch 기반 배포에서 **GitHub Actions 전용 배포 방식**으로 전환하는 과정을 정리한다.

## 🔄 1. 두 가지 배포 방식

| 구분 | gh-pages Branch 방식 | GitHub Actions 전용 방식 |
| --- | --- | --- |
| Branch | `main` + `gh-pages` | 배포용 Branch 불필요 (`main`에서 빌드 가능) |
| Pages 설정 | Deploy from a branch | GitHub Actions |
| 배포 파일 | `gh-pages`에 HTML 저장 | Actions의 Artifact로 업로드 |
| Workflow 파일 | 직접 작성하거나 배포 명령어 사용 | GitHub 제공 템플릿을 수정하여 사용 |

### gh-pages Branch 방식

MkDocs에서 생성한 HTML 파일을 별도의 `gh-pages` Branch에 저장하고, GitHub Pages가 해당 Branch의 파일을 게시하는 방식이다.

### GitHub Actions 전용 방식

`main` Branch에 저장된 Markdown 파일을 GitHub Actions가 자동으로 HTML로 변환한 후 GitHub Pages에 직접 배포하는 방식이다.

별도의 `gh-pages` Branch를 관리할 필요가 없으며, 빌드와 배포 과정을 하나의 Workflow에서 처리할 수 있다.

---

## ⚙️ 2. 전환 순서

### 1. 기존 Workflow 파일 삭제

GitHub Repository의 `.github/workflows/` 폴더로 이동한다.

기존에 `gh-pages` Branch로 배포하도록 작성한 Workflow 파일을 삭제한다.

기존 Workflow를 그대로 남겨두면 서로 다른 배포 방식이 동시에 실행될 수 있으므로 주의한다.

### 2. GitHub Pages 설정 변경

1. Repository의 **Settings**로 이동한다.
2. 왼쪽 메뉴에서 **Pages**를 선택한다.
3. **Build and deployment → Source** 항목을 찾는다.
4. `Deploy from a branch`를 **GitHub Actions**로 변경한다.

이제 GitHub Pages는 Actions에서 생성한 빌드 결과물을 배포할 수 있다.

### 3. 새 Workflow 파일 생성

1. Pages 설정에서 GitHub Actions의 **Static HTML** 템플릿을 선택하거나 Repository에서 직접 파일을 생성한다.
2. `.github/workflows/deploy.yml` 파일을 만든다.
3. 기존 템플릿의 내용을 MkDocs에 맞게 수정한다.

### 4. Workflow 파일 수정

GitHub가 제공하는 기본 Static HTML 배포 Workflow에 **Python 설치, MkDocs 의존성 설치, HTML 빌드 과정**을 추가한다.

```yaml
# GitHub Pages 배포 Workflow
name: Deploy static content to Pages

on:
  # main Branch에 Push하면 실행
  push:
    branches: ["main"]

  # Actions 탭에서 수동 실행 가능
  workflow_dispatch:

# GitHub Pages 배포 권한
permissions:
  contents: read
  pages: write
  id-token: write

# 중복 배포 방지
concurrency:
  group: "pages"
  cancel-in-progress: false

jobs:
  deploy:
    environment:
      name: github-pages
      url: ${{ steps.deployment.outputs.page_url }}

    runs-on: ubuntu-latest

    steps:
      # Repository 파일 가져오기
      - name: Checkout
        uses: actions/checkout@v4

      # 가상 서버에 Python 설치
      - name: Set up Python
        uses: actions/setup-python@v5
        with:
          python-version: '3.x'

      # MkDocs 및 테마 의존성 설치
      - name: Install dependencies
        run: pip install mkdocs-material mkdocs-redirects

      # Markdown 문서를 HTML 웹사이트로 빌드
      # site 폴더 생성
      - name: Build with MkDocs
        run: mkdocs build

      # GitHub Pages 설정
      - name: Setup Pages
        uses: actions/configure-pages@v5

      # 빌드 결과물인 site 폴더 업로드
      - name: Upload artifact
        uses: actions/upload-pages-artifact@v5
        with:
          path: './site'

      # GitHub Pages에 배포
      - name: Deploy to GitHub Pages
        id: deployment
        uses: actions/deploy-pages@v5
```

## 📋 3. Workflow 주요 설정 설명

| 항목 | 설명 |
| --- | --- |
| `on.push` | `main` Branch에 Push하면 Workflow 실행 |
| `workflow_dispatch` | GitHub Actions에서 수동 실행 허용 |
| `permissions` | Repository 읽기 및 Pages 배포 권한 지정 |
| `concurrency` | 여러 배포 작업이 동시에 실행되지 않도록 제어 |
| `checkout` | Repository 파일을 가상 서버로 가져오기 |
| `setup-python` | Python 실행 환경 구성 |
| `Install dependencies` | MkDocs와 필요한 패키지 설치 |
| `mkdocs build` | Markdown 파일을 HTML로 변환 |
| `configure-pages` | GitHub Pages 배포 환경 설정 |
| `upload-pages-artifact` | 생성된 `site/` 폴더 업로드 |
| `deploy-pages` | 업로드한 파일을 실제 웹사이트에 배포 |

### 기존 템플릿에서 변경한 부분

GitHub의 기본 Static HTML 템플릿은 이미 만들어진 HTML 파일을 배포하도록 구성되어 있다.

하지만 MkDocs는 Markdown 파일을 HTML로 변환하는 과정이 필요하므로 다음 세 단계가 추가된다.

1. **Python 설치:** `actions/setup-python`
2. **MkDocs 설치:** `pip install mkdocs-material mkdocs-redirects`
3. **사이트 빌드:** `mkdocs build`

또한 Artifact 업로드 경로를 Repository 전체가 아닌 **`./site`**로 변경한다.

`mkdocs-redirects`는 페이지 주소 변경 시 리디렉션을 설정하는 플러그인으로, 사용하지 않는다면 설치 명령어에서 제외할 수 있다.

## ✅ 4. 배포 확인

Workflow 파일을 수정하고 Commit하면 `main` Branch에 Push 이벤트가 발생하여 GitHub Actions가 실행된다.

1. Repository의 **Actions** 탭으로 이동한다.
2. `Deploy static content to Pages` Workflow를 선택한다.
3. 실행 상태를 확인한다.
4. 초록색 체크 표시가 나타나면 배포가 완료된 것이다.
5. 웹사이트 주소에 접속하여 변경 사항을 확인한다.

배포 오류가 발생했다면 해당 Workflow의 실행 로그에서 어느 단계가 실패했는지 확인한다.

!!! note "기존 Branch 정리"

    GitHub Actions 직접 배포 방식으로 전환한 뒤에는 `gh-pages` Branch가 필요하지 않다. 다만 전환 직후에는 바로 삭제하기보다 새로운 배포 방식이 정상적으로 작동하는지 먼저 확인하는 것이 좋다.

---

## 📝 5. 정리

기존의 `gh-pages` Branch 방식은 빌드된 웹사이트를 별도의 Branch에 저장하는 방식이다.

반면 GitHub Actions 전용 방식은 `main` Branch의 원본 파일을 기반으로 빌드와 배포를 진행하므로 별도의 배포용 Branch가 필요하지 않다.

앞으로는 Markdown 파일을 수정하고 GitHub에 Push하면 **GitHub Actions가 자동으로 MkDocs 빌드와 GitHub Pages 배포를 수행**한다.
